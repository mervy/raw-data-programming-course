Perguntas conceituais — respostas

Q1

O que C quer de você

O artigo #01 diz que C "confia no programador". O que isso significa na prática? Cite duas coisas que a linguagem não faz por você e que linguagens como Python ou Java fazem.

Significa que o compilador gera exatamente o que foi pedido, sem verificações escondidas no caminho: o custo de cada operação fica visível, e a responsabilidade pelos erros também. Duas coisas que C não faz:

  • Verificar limites de vetor: v[10] num vetor de 10 elementos compila e executa, lendo ou escrevendo memória que não é do vetor (comportamento indefinido).
  • Liberar memória: o que foi alocado com malloc fica alocado até um free; não há coletor de lixo.

Outras respostas válidas: não inicializa variáveis locais, não detecta estouro de inteiro com sinal, não tem exceções (erros voltam como valor de retorno).

Q2

Tamanho dos tipos

Por que o padrão C não fixa que int tem 32 bits? O que ele garante sobre char, short, int e long? Quando usar int32_t de <stdint.h>?

Porque C nasceu para rodar em máquinas muito diferentes, e o int deve ser o tamanho "natural" de cada uma. O padrão garante só mínimos e uma ordem: char tem pelo menos 8 bits e sizeof(char) é 1 por definição; short e int têm pelo menos 16 bits; long pelo menos 32; e sizeof(short) <= sizeof(int) <= sizeof(long) <= sizeof(long long).

Use int32_t (e companhia) quando o tamanho exato importa: formatos de arquivo, protocolos de rede, registradores de hardware. Para contadores e índices comuns, int ou size_t bastam.

Q3

Passagem por valor

"Em C, toda passagem de argumento é por valor." Explique a frase e diga como, então, uma função consegue alterar uma variável de quem a chamou.

A função recebe cópias dos argumentos: alterar o parâmetro dentro dela não muda a variável original. Para alterar a variável de quem chamou, passa-se o endereço dela (um ponteiro); o ponteiro também é copiado, mas a cópia aponta para o mesmo lugar, e *p = ... escreve na variável original. É o caso do scanf("%d", &x).

Q4

switch e o break esquecido

O que acontece quando um case de um switch não termina com break? Dê uma situação em que isso é intencional.

A execução continua no case seguinte (fall-through), sem testar o rótulo dele. É intencional quando vários valores levam à mesma ação:

switch (c) {
case 'a': case 'e': case 'i': case 'o': case 'u':
    vogais++;
    break;
default:
    outras++;
}

Quando não é intencional, é bug; o gcc e o clang avisam com -Wimplicit-fallthrough, e o C23 tem o atributo [[fallthrough]] para marcar o caso desejado.

Q5

Vetor como argumento

Por que, dentro de uma função void f(int v[]), a expressão sizeof v / sizeof v[0] não dá o número de elementos? Como as funções da biblioteca resolvem isso?

Porque um parâmetro declarado como vetor é um ponteiro: o vetor "decai" para o endereço do primeiro elemento na chamada. Dentro de f, sizeof v é o tamanho de um ponteiro (8 bytes num sistema de 64 bits), não do vetor. A solução é passar o tamanho junto, como fazem qsort(base, n, tamanho, cmp), memcpy(dest, orig, n) e fgets(buf, tamanho, arquivo); strings resolvem de outro jeito, com o '\0' no fim.

Entre inteiros, / descarta a parte fracionária em direção ao zero (desde o C99), por isso -7 / 2 é -3, e o resto acompanha o sinal do dividendo: -7 % 2 é -1. Q7

Troca com ponteiros

Escreva void troca(int *a, int *b) que troca os valores de duas variáveis e mostre, no mesmo programa, por que uma versão void troca_errada(int a, int b) não funciona.

#include <stdio.h>

void troca_errada(int a, int b) {
    int t = a;
    a = b;
    b = t;  /* troca as cópias, que somem ao retornar */
}

void troca(int *a, int *b) {
    int t = *a;
    *a = *b;
    *b = t;
}

int main(void) {
    int x = 1, y = 2;
    troca_errada(x, y);
    printf("depois de troca_errada: x=%d y=%d\n", x, y);
    troca(&x, &y);
    printf("depois de troca:        x=%d y=%d\n", x, y);
    return 0;
}
depois de troca_errada: x=1 y=2
depois de troca:        x=2 y=1

troca_errada recebe cópias de x e y; troca recebe os endereços, e o * escreve nas variáveis do main.

Q8

Laços e o do-while

Escreva um programa que leia números inteiros da entrada até chegar um 0 e mostre quantos foram lidos (sem contar o zero), a soma e a média com uma casa decimal. Use do-while e trate o caso de nenhum número antes do zero.

#include <stdio.h>

int main(void) {
    int n, quantos = 0;
    long soma = 0;

    do {
        if (scanf("%d", &n) != 1)  /* entrada acabou ou não é número */
            break;
        if (n != 0) {
            soma += n;
            quantos++;
        }
    } while (n != 0);

    if (quantos == 0) {
        printf("nenhum número lido\n");
        return 0;
    }
    printf("lidos: %d, soma: %ld, média: %.1f\n", quantos, soma, (double) soma / quantos);
    return 0;
}

Entrada digitada:

8 3 10 4 0
lidos: 4, soma: 25, média: 6.2

O scanf devolve quantos itens converteu: testar != 1 evita um laço infinito quando a entrada termina ou tem texto. A soma é long e a média converte para double antes de dividir.

A média é 6,25 e aparece como 6.2, não 6.3. O valor 6,25 é exato em binário, e o printf desempata arredondando para o dígito par. Já 6.35 vira 6.3 por outro motivo: em binário ele é 6,3499999…, então nem chega a ser empate.

Q9

Busca do maior e do segundo maior

Escreva uma função void dois_maiores(const int v[], int n, int *maior, int *segundo) que encontra, numa única passada, o maior e o segundo maior valor distintos do vetor. Teste com {5, 9, 2, 9, 7}.

#include <stdio.h>
#include <limits.h>

void dois_maiores(const int v[], int n, int *maior, int *segundo) {
    *maior = *segundo = INT_MIN;
    for (int i = 0; i < n; i++) {
        if (v[i] > *maior) {
            *segundo = *maior;
            *maior = v[i];
        } else if (v[i] < *maior && v[i] > *segundo) {
            *segundo = v[i];  /* "<" e não "!=": repetir o maior não o torna segundo */
        }
    }
}

int main(void) {
    int v[] = {5, 9, 2, 9, 7};
    int m, s;
    dois_maiores(v, sizeof v / sizeof v[0], &m, &s);
    printf("maior: %d, segundo: %d\n", m, s);
    return 0;
}
maior: 9, segundo: 7

Aqui sizeof v / sizeof v[0] funciona porque v é o vetor de verdade, no main; dentro da função ele já seria só um ponteiro. INT_MIN como valor inicial dispensa tratar o primeiro elemento à parte. Se todos os valores forem iguais, segundo continua INT_MIN, e quem chama precisa tratar esse caso.

Q10

Vetor e ponteiro não são a mesma coisa

int v[5] e int *p = v permitem escrever v[2] e p[2]. Cite duas diferenças reais entre v e p.

  • sizeof v é o tamanho do vetor inteiro (20 bytes com int de 4), e sizeof p é o tamanho de um ponteiro.
  • v não é uma variável que se possa reatribuir: v = outro não compila, enquanto p = outro é normal.
  • &v tem tipo "ponteiro para vetor de 5 int" (int (*)[5]), e &p é "ponteiro para ponteiro" (int **).

O que elas têm em comum: na maioria das expressões, v decai para &v[0], e v[i] é definido como *(v + i).

Q11

Aritmética de ponteiros

Se p é um int * que vale 0x1000 e int tem 4 bytes, quanto vale p + 3? E se p fosse um char *? O que significa subtrair dois ponteiros?

p + 3 avança 3 elementos, não 3 bytes: com int de 4 bytes vale 0x100C; com char * valeria 0x1003. Subtrair dois ponteiros para o mesmo vetor dá a distância em elementos, do tipo ptrdiff_t; subtrair ponteiros de vetores diferentes é comportamento indefinido.

Q12

O '\0' e o tamanho da string

Qual a diferença entre sizeof e strlen aplicados a char s[20] = "casa";? Por que char t[4] = "casa"; é perigoso?

sizeof s é 20 (o tamanho do vetor) e strlen(s) é 4 (os caracteres antes do '\0'). Em char t[4] = "casa"; o literal tem 5 caracteres contando o '\0'; C permite a inicialização, mas descarta o terminador. t não é uma string válida, e strlen(t) ou printf("%s", t) continuam lendo memória até achar um zero por acaso.

Q13

Literal de string

Por que char *s = "texto"; s[0] = 'T'; pode derrubar o programa, enquanto char s[] = "texto"; s[0] = 'T'; funciona?

No primeiro caso, s aponta para o próprio literal, que costuma ficar numa área somente leitura; modificá-lo é comportamento indefinido e, na prática, dá falha de segmentação. No segundo, s é um vetor local inicializado com uma cópia do literal, e a cópia é modificável. Por isso o hábito de declarar const char *s = "texto";: o compilador passa a recusar a escrita.

Q16

Argumentos de linha de comando

Escreva um programa que receba números pela linha de comando e imprima a soma. Argumentos que não forem números inteiros devem ser avisados em stderr e ignorados. Use strtol, não atoi, e diga por quê.

#include <stdio.h>
#include <stdlib.h>
#include <errno.h>

int main(int argc, char *argv[]) {
    long soma = 0;
    for (int i = 1; i < argc; i++) {
        char *fim;
        errno = 0;
        long n = strtol(argv[i], &fim, 10);
        if (fim == argv[i] || *fim != '\0' || errno == ERANGE) {
            fprintf(stderr, "ignorado: %s\n", argv[i]);
            continue;
        }
        soma += n;
    }
    printf("soma: %ld\n", soma);
    return 0;
}

Executado sem argumentos, o programa imprime:

soma: 0

Com ./soma 10 abc 5 7x 20, a saída é ignorado: abc, ignorado: 7x e soma: 35. O atoi devolve 0 tanto para "0" quanto para "abc" e não tem como avisar o erro; o strtol informa onde parou (fim) e sinaliza estouro em errno. Testar *fim != '\0' recusa "7x", que o atoi aceitaria como 7.

Q17

Pilha ou heap

Para cada variável, diga onde ela vive e quando deixa de existir: (a) um int local de uma função; (b) uma variável static dentro de uma função; (c) o bloco devolvido por malloc; (d) uma variável global.

  • (a) Na pilha: nasce na entrada da função e some no retorno. Devolver o endereço dela é bug.
  • (b) Na área de dados estáticos: existe do início ao fim do programa e mantém o valor entre chamadas.
  • (c) No heap: existe até um free, independentemente da função que alocou.
  • (d) Também na área estática, durante toda a execução.
Q18

realloc sem perder memória

Por que p = realloc(p, novo_tamanho); é um padrão perigoso? Escreva a forma correta.

Se o realloc falhar, ele devolve NULL e o bloco antigo continua alocado. Atribuindo direto a p, o único ponteiro para o bloco é sobrescrito: vazamento, e os dados antigos ficam inacessíveis. O certo é usar um temporário:

int *tmp = realloc(p, novo * sizeof *tmp);
if (tmp == NULL) {
    /* p ainda é válido: trate o erro e libere quando for o caso */
} else {
    p = tmp;
}
Q19

calloc e malloc

Quais as duas diferenças entre malloc(n * sizeof(int)) e calloc(n, sizeof(int))?

O calloc zera a memória (o malloc a entrega com lixo) e recebe quantidade e tamanho separados, o que permite detectar o estouro da multiplicação n * tamanho e devolver NULL em vez de alocar um bloco menor do que o pedido.

Q20

Dangling pointer

O que é um dangling pointer? Dê dois jeitos de criar um e um hábito que reduz o estrago.

É um ponteiro que aponta para memória que não é mais válida. Dois jeitos: usar um ponteiro depois do free do bloco (use-after-free) e devolver o endereço de uma variável local. O hábito de fazer p = NULL; logo depois do free(p) transforma um uso posterior num erro imediato e previsível (desreferenciar NULL derruba o programa na hora), em vez de corromper memória silenciosamente. O AddressSanitizer (-fsanitize=address) detecta os dois casos.

Q21

Vetor que cresce

Implemente um vetor dinâmico de int com push que dobra a capacidade quando enche (comece com capacidade 2). Insira os números de 1 a 10 e mostre a capacidade a cada realocação. Libere tudo no fim.

#include <stdio.h>
#include <stdlib.h>

typedef struct {
    int *dados;
    size_t tam, cap;
} Vetor;

int push(Vetor *v, int x) {
    if (v->tam == v->cap) {
        size_t nova = v->cap ? v->cap * 2 : 2;
        int *tmp = realloc(v->dados, nova * sizeof *tmp);
        if (tmp == NULL)
            return -1;  /* v continua válido */
        v->dados = tmp;
        v->cap = nova;
        printf("capacidade: %zu\n", v->cap);
    }
    v->dados[v->tam++] = x;
    return 0;
}

int main(void) {
    Vetor v = {0};
    for (int i = 1; i <= 10; i++)
        if (push(&v, i) != 0) {
            fprintf(stderr, "sem memória\n");
            free(v.dados);
            return 1;
        }
    for (size_t i = 0; i < v.tam; i++)
        printf("%d ", v.dados[i]);
    printf("\n");
    free(v.dados);
    return 0;
}

Q22

Duplicando uma string

Escreva char *duplica(const char *s), equivalente ao strdup (que só entrou no padrão no C23), e um programa que duplica, modifica a cópia e mostra que o original não mudou.

#include <stdio.h>
#include <stdlib.h>
#include <string.h>

char *duplica(const char *s) {
    size_t n = strlen(s) + 1;  /* +1 para o '\0' */
    char *copia = malloc(n);
    if (copia != NULL)
        memcpy(copia, s, n);
    return copia;
}

int main(void) {
    const char *original = "memória";
    char *copia = duplica(original);
    if (copia == NULL)
        return 1;
    copia[0] = 'M';
    printf("%s / %s\n", original, copia);
    free(copia);
    return 0;
}

O erro clássico é malloc(strlen(s)), sem o +1: a cópia do '\0' escreve um byte fora do bloco. Quem recebe o ponteiro passa a ser dono da memória e precisa fazer o free.

Q23

Achando o vazamento

O programa abaixo vaza memória. Encontre os dois vazamentos, corrija e diga qual ferramenta do curso confirmaria a correção.

#include <stdlib.h>
#include <string.h>

char *saudacao(const char *nome) {
    char *s = malloc(strlen(nome) + 7);
    strcpy(s, "Olá, ");
    strcat(s, nome);
    return s;
}

int main(void) {
    for (int i = 0; i < 3; i++) {
        char *msg = saudacao("Ana");
        msg = saudacao("Bia");
        free(msg);
    }
    return 0;
}

Os dois vazamentos: em cada volta, o resultado de saudacao("Ana") é perdido quando msg recebe saudacao("Bia"); e o tamanho também está errado, porque "Olá, " tem 6 bytes em UTF-8 (o á ocupa 2) e, somando o '\0', o + 7 só cabe por sorte. Corrigido:

#include <stdio.h>
#include <stdlib.h>
#include <string.h>

char *saudacao(const char *nome) {
    const char *prefixo = "Olá, ";
    char *s = malloc(strlen(prefixo) + strlen(nome) + 1);
    if (s == NULL)
        return NULL;
    strcpy(s, prefixo);
    strcat(s, nome);
    return s;
}

int main(void) {
    for (int i = 0; i < 3; i++) {
        char *msg = saudacao("Ana");
        printf("%s\n", msg ? msg : "(sem memória)");
        free(msg);
        msg = saudacao("Bia");
        printf("%s\n", msg ? msg : "(sem memória)");
        free(msg);
    }
    return 0;
}

Q24

Padding em structs

Por que sizeof de struct { char c; int i; char d; } costuma ser 12 e não 6? Como reordenar os campos para gastar menos?

Por alinhamento: o processador acessa um int de 4 bytes mais rápido (e algumas arquiteturas só conseguem) num endereço múltiplo de 4. O compilador insere 3 bytes de preenchimento depois de c e mais 3 no fim (para que um vetor dessas structs mantenha cada i alinhado): 1 + 3 + 4 + 1 + 3 = 12. Colocando os campos do maior para o menor, struct { int i; char c; char d; } ocupa 8.

Q25

union

O que é uma union e qual o perigo de ler um campo diferente do último escrito? Dê um uso legítimo.

Numa union todos os campos ocupam o mesmo endereço, e o tamanho é o do maior campo. Só o último campo escrito tem valor significativo; ler outro reinterpreta os bytes (em C isso é permitido para ver a representação, mas o resultado depende da plataforma). O uso legítimo mais comum é a união etiquetada: uma struct com um enum dizendo qual campo da union está valendo, como num valor que pode ser número ou texto.

Q26

Macros com efeito colateral

Por que #define QUADRADO(x) x * x está errado duas vezes? Corrija e mostre um caso que nem a versão corrigida resolve.

Primeiro, falta parêntese: QUADRADO(1 + 2) vira 1 + 2 * 1 + 2, que dá 5. Segundo, QUADRADO(a) / QUADRADO(b) também se desarranja sem o parêntese externo. A versão correta é #define QUADRADO(x) ((x) * (x)). Mesmo assim, QUADRADO(i++) incrementa i duas vezes (e sem ponto de sequência entre elas: comportamento indefinido), porque a macro copia o texto do argumento. Uma função static inline não tem esse problema.

Q27

static e extern

Explique os dois significados de static: numa variável dentro de uma função e numa função ou variável no escopo do arquivo. E para que serve extern?

Dentro de uma função, static muda a duração: a variável existe durante todo o programa e guarda o valor entre chamadas. No escopo do arquivo, muda a ligação: a função ou variável fica visível só naquele .c (ligação interna), o que evita colisão de nomes entre arquivos. extern declara que uma variável global existe em outro lugar; aparece no cabeçalho (extern int contador;), enquanto um único .c faz a definição (int contador = 0;).

Q28

Include guard

Para que serve o trecho #ifndef PILHA_H / #define PILHA_H / ... / #endif num cabeçalho? O que acontece sem ele?

Impede que o conteúdo do cabeçalho seja processado duas vezes no mesmo arquivo .c, o que acontece quando dois cabeçalhos incluem um terceiro. Sem a guarda, definições como a de uma struct ou de um typedef aparecem duplicadas e a compilação falha com "redefinition". #pragma once faz o mesmo e é aceito por todos os compiladores populares, mas não é padrão.

Q33

scanf e o '\n' que sobra

Por que, depois de scanf("%d", &idade);, um fgets(nome, sizeof nome, stdin); parece "pular" a leitura? Como resolver?

O scanf("%d") lê o número e para antes do '\n' que o usuário digitou com o Enter. O fgets seguinte encontra esse '\n' no buffer e termina na hora, com uma linha vazia. Soluções: ler tudo com fgets e converter com sscanf/strtol (o caminho mais robusto), ou descartar o resto da linha depois do scanf com int c; while ((c = getchar()) != '\n' && c != EOF);.

Q34

Modo texto e binário

Qual a diferença entre abrir um arquivo com "r" e com "rb"? Em que sistema ela aparece de verdade?

Em modo texto a biblioteca pode traduzir o fim de linha: no Windows, "\r\n" vira '\n' na leitura e o contrário na escrita, e um byte 0x1A pode ser tratado como fim de arquivo. Em modo binário os bytes passam sem alteração. No Linux e no macOS os dois modos são idênticos; no Windows, ler um arquivo binário (imagem, struct gravada com fwrite) em modo texto corrompe os dados.

Q35

feof no lugar errado

Por que o laço while (!feof(f)) { fgets(linha, sizeof linha, f); ... } costuma processar a última linha duas vezes?

Porque feof só fica verdadeiro depois que uma leitura tenta passar do fim. Após ler a última linha, feof ainda é falso; o laço roda de novo, o fgets falha (devolve NULL e não altera linha) e o corpo processa o conteúdo antigo outra vez. O certo é testar o retorno da própria leitura: while (fgets(linha, sizeof linha, f) != NULL) { ... }.

Q36

rand e a semente

O que faz srand(time(NULL))? Por que chamá-lo dentro de um laço, antes de cada rand(), é um erro?

Define a semente do gerador pseudoaleatório a partir do relógio, para que cada execução produza uma sequência diferente. Chamado dentro do laço, ele reinicia o gerador várias vezes no mesmo segundo (time tem resolução de segundos) com a mesma semente, e rand() devolve o mesmo número repetidamente. A semente deve ser definida uma vez, no início do programa. E rand() não serve para nada de segurança, como senhas ou tokens.

#include <stdlib.h>
#include <math.h>

}

    double mediana = n % 2 ? v[n / 2] : (v[n / 2 - 1] + v[n / 2]) / 2;

Q42

Recursão e a pilha

O que é estouro de pilha (stack overflow) numa função recursiva? O que é recursão de cauda e por que o padrão C não garante que ela economize pilha?

Cada chamada guarda parâmetros, variáveis locais e o endereço de retorno num quadro da pilha; uma recursão profunda demais (ou sem caso base) esgota a pilha, de alguns megabytes, e o sistema derruba o programa. Na recursão de cauda, a chamada recursiva é a última coisa que a função faz, e o compilador pode reaproveitar o quadro atual, transformando a recursão num laço. O padrão C não obriga essa otimização: o gcc e o clang a fazem com -O2, mas não sem otimização. Código que depende dela para não estourar a pilha deve virar laço explícito.

Q43

Operações com bits

Escreva as expressões para, num unsigned chamado flags: ligar o bit 3, desligar o bit 5, inverter o bit 0 e testar se o bit 7 está ligado. Por que usar tipos sem sinal para isso?

  • Ligar o bit 3: flags |= 1u << 3;
  • Desligar o bit 5: flags &= ~(1u << 5);
  • Inverter o bit 0: flags ^= 1u << 0;
  • Testar o bit 7: if (flags & (1u << 7))

Com tipos sem sinal, os deslocamentos e o ~ têm comportamento totalmente definido. Com sinal, deslocar um 1 para o bit de sinal (1 << 31 num int de 32 bits) é comportamento indefinido, e deslocar negativos para a direita depende da implementação. Por isso o sufixo u em 1u.

    int n = 0;
    while (x) {
        x &= x - 1;  /* apaga o bit 1 mais baixo */
        n++;
    }
    return n;
}

int potencia_de_2(unsigned x) {
    return x != 0 && (x & (x - 1)) == 0;
}

int main(void) {
    unsigned testes[] = {0, 1, 12, 64, 255};
    for (int i = 0; i < 5; i++)
        printf("%3u: %d bits ligados, %s\n", testes[i], conta_bits(testes[i]),
               potencia_de_2(testes[i]) ? "potência de 2" : "não é potência de 2");
    return 0;
}
  0: 0 bits ligados, não é potência de 2
  1: 1 bits ligados, potência de 2
 12: 2 bits ligados, não é potência de 2
 64: 1 bits ligados, potência de 2
255: 8 bits ligados, não é potência de 2

Subtrair 1 troca o bit 1 mais baixo por 0 e todos os zeros abaixo dele por 1; o & com o valor original apaga exatamente esse bit. O laço roda uma vez por bit ligado, não por bit do tipo. Uma potência de 2 tem um único bit ligado, então x & (x - 1) dá zero. O gcc e o clang oferecem __builtin_popcount, que vira uma única instrução nos processadores modernos.

Q48

Lista ou vetor

Compare lista encadeada e vetor dinâmico em: acesso ao i-ésimo elemento, inserção no início, uso de memória e aproveitamento do cache do processador. Quando a lista ganha?

  • Acesso por índice: vetor O(1); lista O(n), porque precisa percorrer os nós.
  • Inserção no início: lista O(1) (só ajusta ponteiros); vetor O(n), porque desloca todos os elementos.
  • Memória: a lista gasta um ou dois ponteiros por nó, além do custo de cada malloc.
  • Cache: o vetor é contíguo e muito mais rápido de percorrer; os nós da lista ficam espalhados pelo heap.

A lista ganha quando há muitas inserções e remoções no meio a partir de um nó que já se tem em mãos, ou quando os elementos não podem mudar de endereço. Na maioria dos outros casos, o vetor é mais rápido mesmo nas operações em que a teoria favorece a lista.

Q49

Árvore desbalanceada

Em que ordem de inserção uma árvore binária de busca vira uma "lista"? Qual o custo da busca nesse caso e que tipos de árvore evitam o problema?

Inserindo os valores já ordenados (1, 2, 3, 4…) ou em ordem decrescente: cada novo nó vira filho direito (ou esquerdo) do anterior, e a altura passa a ser n. A busca cai de O(log n) para O(n). Árvores autobalanceadas, como a AVL e a rubro-negra, fazem rotações a cada inserção e remoção para manter a altura em O(log n).

Q50

Colisões numa tabela hash

O que é uma colisão numa tabela hash? Explique o encadeamento separado e diga o que é o fator de carga e por que ele importa.

Colisão é quando duas chaves diferentes caem no mesmo índice da tabela. No encadeamento separado, cada posição guarda uma lista com todas as chaves daquele índice. O fator de carga é o número de elementos dividido pelo número de posições: quanto maior, mais longas as listas e mais lenta a busca. Por isso as implementações redimensionam a tabela (dobram o tamanho e reinserem tudo) quando o fator passa de um limite, em torno de 0,75.

Lista encadeada com inversão

Implemente uma lista simplesmente encadeada de int com insere_inicio, imprime, inverte (no lugar, sem alocar nós) e libera. Teste inserindo 1, 2, 3 e 4.

#include <stdio.h>
#include <stdlib.h>

typedef struct No {
    int valor;
    struct No *prox;
} No;

int insere_inicio(No **lista, int valor) {
    No *novo = malloc(sizeof *novo);
    if (novo == NULL)
        return -1;
    novo->valor = valor;
    novo->prox = *lista;
    *lista = novo;  /* ponteiro para ponteiro: muda a cabeça da lista de quem chamou */
    return 0;
}

void imprime(const No *p) {
    for (; p; p = p->prox)
        printf("%d -> ", p->valor);
    printf("NULL\n");
}

No *inverte(No *p) {
    No *anterior = NULL;
    while (p) {
        No *prox = p->prox;
        p->prox = anterior;
        anterior = p;
        p = prox;
    }
    return anterior;
}

void libera(No *p) {
    while (p) {
        No *prox = p->prox;  /* guarda antes do free */
        free(p);
        p = prox;
    }
}

int main(void) {
    No *lista = NULL;
    for (int i = 1; i <= 4; i++)
        insere_inicio(&lista, i);
    imprime(lista);
    lista = inverte(lista);
    imprime(lista);
    libera(lista);
    return 0;
}

1 -> 2 -> 3 -> 4 -> NULL

insere_inicio recebe No ** porque precisa alterar o ponteiro da cabeça que pertence ao main. Em libera, ler p->prox depois do free(p) seria use-after-free; por isso o próximo é guardado antes.

#include <stdio.h>

int balanceado(const char *s) {
    char pilha[256];

    for (; *s; s++) {
        switch (*s) {
        case '(': case '[': case '{':
            if (topo == (int) sizeof pilha)

            if (topo == 0 || pilha[--topo] != esperado)
                return 0;
            break;
        }
        }
    }

}

    const char *testes[] = { "{a[b(c)d]e}", "(a[b)c]", "((x)", "x + y" };

Q53

Árvore binária de busca

Implemente uma BST de inteiros com insere, busca, percurso em ordem e altura. Insira 50, 30, 70, 20, 40, 60, 80 e mostre a altura; depois mostre a altura inserindo de 1 a 7 em ordem.

#include <stdio.h>
#include <stdlib.h>

typedef struct No { int v; struct No *esq, *dir; } No;

No *insere(No *r, int v) {
    if (r == NULL) {
        No *n = calloc(1, sizeof *n);
        if (n)
            n->v = v;
        return n;
    }
    if (v < r->v)
        r->esq = insere(r->esq, v);
    else if (v > r->v)
        r->dir = insere(r->dir, v);
    return r;  /* valor repetido: ignorado */
}

int busca(const No *r, int v) {
    while (r && r->v != v)
        r = v < r->v ? r->esq : r->dir;
    return r != NULL;
}

void em_ordem(const No *r) {
    if (!r) return;
    em_ordem(r->esq);
    printf("%d ", r->v);
    em_ordem(r->dir);
}

int altura(const No *r) {
    if (!r) return 0;
    int e = altura(r->esq), d = altura(r->dir);
    return 1 + (e > d ? e : d);
}

void libera(No *r) {
    if (!r) return;
    libera(r->esq);
    libera(r->dir);
    free(r);
}

int main(void) {
    int valores[] = {50, 30, 70, 20, 40, 60, 80};
    No *a = NULL, *b = NULL;
    for (int i = 0; i < 7; i++) {
        a = insere(a, valores[i]);
        b = insere(b, i + 1);
    }
    em_ordem(a);
    printf("\nbusca 60: %d, busca 65: %d\n", busca(a, 60), busca(a, 65));
    printf("altura (ordem misturada): %d\n", altura(a));
    printf("altura (1 a 7 em ordem):  %d\n", altura(b));
    libera(a);
    libera(b);
    return 0;
}

busca 60: 1, busca 65: 0
altura (ordem misturada): 3

Q54

Tabela hash de contagem de palavras

Implemente uma tabela hash com encadeamento (31 posições, função djb2) que conta quantas vezes cada palavra aparece em "o rato roeu a roupa do rei de roma e o rei riu do rato". Imprima as palavras que aparecem mais de uma vez.

#include <stdio.h>
#include <stdlib.h>
#include <string.h>

#define TAM 31

typedef struct Entrada {
    char *palavra;
    int conta;
    struct Entrada *prox;
} Entrada;

static unsigned long djb2(const char *s) {
    unsigned long h = 5381;
    for (; *s; s++)
        h = h * 33 + (unsigned char) *s;
    return h;
}

static int conta(Entrada *tabela[], const char *palavra) {
    unsigned long i = djb2(palavra) % TAM;
    for (Entrada *e = tabela[i]; e; e = e->prox)
        if (strcmp(e->palavra, palavra) == 0)
            return ++e->conta;
    Entrada *nova = malloc(sizeof *nova);
    if (!nova || !(nova->palavra = malloc(strlen(palavra) + 1))) {
        free(nova);
        return -1;
    }
    strcpy(nova->palavra, palavra);
    nova->conta = 1;
    nova->prox = tabela[i];
    tabela[i] = nova;
    return 1;
}

int main(void) {
    char texto[] = "o rato roeu a roupa do rei de roma e o rei riu do rato";
    Entrada *tabela[TAM] = {0};
    for (char *p = strtok(texto, " "); p; p = strtok(NULL, " "))
        if (conta(tabela, p) < 0)
            return 1;

    for (int i = 0; i < TAM; i++)
        for (Entrada *e = tabela[i]; e; e = e->prox)
            if (e->conta > 1)
                printf("%s: %d\n", e->palavra, e->conta);

    for (int i = 0; i < TAM; i++)
        for (Entrada *e = tabela[i], *prox; e; e = prox) {
            prox = e->prox;
            free(e->palavra);
            free(e);
        }
    return 0;
}
rei: 2
rato: 2
do: 2
o: 2

A ordem da saída é a ordem dos índices da tabela, não a alfabética nem a de aparição: uma tabela hash não guarda ordem. O strtok modifica a string (troca os espaços por '\0'), por isso texto é um vetor e não um ponteiro para literal; ele também não é seguro com threads (há strtok_r no POSIX).

Q55

Comportamento indefinido

O que é comportamento indefinido (UB)? Por que "no meu computador funciona" não prova nada? Cite três exemplos.

É uma construção para a qual o padrão não impõe nenhum requisito: o programa pode funcionar, travar, dar resultado errado ou mudar de comportamento com outro compilador, outra flag de otimização ou outra versão. O otimizador parte do princípio de que UB nunca acontece e pode remover código com base nisso, então o mesmo programa que "funciona" com -O0 quebra com -O2. Exemplos: estouro de int com sinal, acesso fora dos limites de um vetor, desreferenciar NULL ou um ponteiro liberado, ler variável não inicializada, modificar a mesma variável duas vezes sem ponto de sequência (i = i++).

Q56

Sanitizers ou Valgrind

Qual a diferença de funcionamento entre o AddressSanitizer e o Valgrind? Cite uma vantagem de cada.

O AddressSanitizer é ativado na compilação (-fsanitize=address): o compilador instrumenta cada acesso à memória. É rápido (o programa fica cerca de 2 vezes mais lento) e pega estouros na pilha e em variáveis globais. O Valgrind executa o binário já pronto numa máquina virtual que observa cada instrução: não exige recompilar e detecta leitura de memória não inicializada (no sanitizer isso é o MemorySanitizer, só no clang), mas deixa o programa de 20 a 50 vezes mais lento. Os dois não devem ser usados juntos no mesmo binário.

Q57

O que o make sabe

Como o make decide o que recompilar? O que acontece se o Makefile não declarar que main.o depende de pilha.h?

Pela data de modificação: um alvo é refeito se não existir ou se algum pré-requisito listado for mais novo que ele. Se pilha.h não estiver entre os pré-requisitos de main.o, mudar o cabeçalho não recompila main.c, e o executável pode misturar um main.o com o layout antigo de uma struct e um pilha.o com o novo: um bug difícil de entender. As flags -MMD -MP fazem o compilador gerar essas dependências automaticamente.

Q58

errno

Como funciona o errno? Por que é errado testar errno sem antes verificar o valor de retorno da função?

errno é um valor por thread que as funções da biblioteca ajustam quando falham, com códigos como ENOENT ou EACCES (strerror(errno) e perror dão a mensagem). Mas uma função bem-sucedida pode deixar errno com qualquer valor, inclusive o de uma falha interna já resolvida. Por isso o protocolo é: primeiro olhar o retorno (NULL, -1, EOF), só então consultar errno. A exceção são funções como strtol, que não têm valor de retorno de erro: nelas se zera o errno antes da chamada e se testa depois.

Q59

assert não é tratamento de erro

Para que serve o assert? Por que é errado usá-lo para validar a entrada do usuário ou o retorno de malloc?

assert(condicao) documenta e verifica uma premissa do programador, algo que só falha se houver bug: um índice dentro dos limites, um ponteiro que nunca deveria ser NULL. Se a condição for falsa, o programa aborta mostrando arquivo e linha. Só que compilar com -DNDEBUG, como se faz em versões de produção, remove todos os assert. Entrada inválida e falta de memória são situações esperadas em produção; precisam de um if com tratamento de verdade, senão a validação some exatamente quando é mais necessária.

Estouro detectado

O código abaixo calcula a média de dois int e falha para valores grandes. Explique o problema e escreva uma versão que nunca estoura. Teste com INT_MAX e INT_MAX - 2.

#include <limits.h>

}

    if (a > b) { int t = a; a = b; b = t; }
    return a + (b - a) / 2;  /* b - a não estoura quando a <= b e os dois têm o mesmo sinal */
}

int main(void) {
    printf("%d\n", media(INT_MAX, INT_MAX - 2));
    printf("%d\n", media_sem_tipo_maior(INT_MAX, INT_MAX - 2));
    printf("%d\n", media(-7, 2));

Q63

Makefile com dependências automáticas

Escreva um Makefile para um projeto com main.c, pilha.c e pilha.h que: compila com -Wall -Wextra -g, gera as dependências de cabeçalhos automaticamente, tem os alvos all e clean e não confunde clean com um arquivo.

	$(CC) $(CFLAGS) -o $@ $^

Q64

fork

O que fork() devolve no processo pai, no filho e em caso de erro? Por que um printf("oi") sem \n antes do fork pode aparecer duas vezes?

No pai, devolve o PID do filho; no filho, devolve 0; em caso de erro, -1 (e nenhum filho é criado). O printf sem \n deixa o texto no buffer de saída da biblioteca, ainda não escrito. O fork copia o processo inteiro, buffer incluído, e cada processo descarrega a sua cópia ao terminar. Por isso se faz fflush(stdout) antes do fork, ou se termina a linha com \n quando a saída é um terminal.

Q65

Zumbis

O que é um processo zumbi e como evitá-lo? E um processo órfão?

Um zumbi é um filho que já terminou mas cujo pai ainda não leu o código de saída com wait/waitpid; ele não consome CPU nem memória, mas ocupa uma entrada na tabela de processos. Evita-se chamando wait (ou tratando SIGCHLD). Um órfão é um filho cujo pai terminou antes dele; ele é adotado pelo init (PID 1) ou por um processo subreaper, que faz o wait por ele.

Q66

Mutex e variável de condição

Por que o pthread_cond_wait precisa receber o mutex? E por que a condição é testada num while, não num if?

O pthread_cond_wait libera o mutex e dorme numa única operação atômica e, ao acordar, readquire o mutex antes de retornar. Se fossem dois passos, um sinal emitido entre liberar e dormir se perderia. O while existe porque a thread pode acordar e encontrar a condição falsa: outra thread pode ter chegado antes e consumido o item, e o padrão permite despertares espúrios, sem nenhum sinal. Por isso se testa de novo depois de acordar.

Q67

O que fazer num tratador de sinal

Por que é errado chamar printf ou malloc dentro de um tratador de sinal? Qual o padrão recomendado?

O sinal pode chegar no meio de qualquer instrução, inclusive dentro de um printf ou malloc que o próprio programa estava executando. Chamá-los de novo no tratador pode corromper as estruturas internas da biblioteca ou causar um impasse num lock interno. Só funções async-signal-safe (como write e _exit) são permitidas. O padrão é o tratador apenas ligar uma variável volatile sig_atomic_t e o laço principal verificá-la e fazer o trabalho de verdade.

Q68

fork, exec e wait

Escreva um programa que cria um processo filho para executar echo com os argumentos "olá do filho", espera o filho terminar e mostra o código de saída dele.

#define _POSIX_C_SOURCE 200809L
#include <stdio.h>
#include <stdlib.h>
#include <unistd.h>
#include <sys/wait.h>

int main(void) {
    fflush(stdout);  /* nada pendente no buffer para ser duplicado pelo fork */
    pid_t pid = fork();
    if (pid < 0) {
        perror("fork");
        return 1;
    }
    if (pid == 0) {
        execlp("echo", "echo", "olá do filho", (char *) NULL);
        perror("execlp");  /* só chega aqui se o exec falhar */
        _exit(127);
    }
    int status;
    if (waitpid(pid, &status, 0) < 0) {
        perror("waitpid");
        return 1;
    }
    if (WIFEXITED(status))
        printf("filho terminou com código %d\n", WEXITSTATUS(status));
    return 0;
}
olá do filho
filho terminou com código 0

O exec substitui o programa do processo filho pelo echo: se der certo, nada depois dele executa. Por isso o tratamento de erro vem logo em seguida, com _exit (e não exit, que descarregaria buffers copiados do pai). Com -std=c17, o #define _POSIX_C_SOURCE é necessário para expor as funções POSIX nos cabeçalhos.

Q69

Somando em paralelo com threads

Some os números de 1 a 10.000.000 dividindo o trabalho entre 4 threads, cada uma com o seu intervalo e o seu resultado parcial, sem nenhum mutex. Explique por que não é preciso mutex.

#include <stdio.h>
#include <pthread.h>

#define N 10000000L
#define THREADS 4

typedef struct { long inicio, fim, parcial; } Tarefa;

static void *soma(void *arg) {
    Tarefa *t = arg;
    t->parcial = 0;
    for (long i = t->inicio; i <= t->fim; i++)
        t->parcial += i;
    return NULL;
}

int main(void) {
    pthread_t th[THREADS];
    Tarefa tarefas[THREADS];
    long bloco = N / THREADS;

    for (int i = 0; i < THREADS; i++) {
        tarefas[i].inicio = i * bloco + 1;
        tarefas[i].fim = (i == THREADS - 1) ? N : (i + 1) * bloco;
        if (pthread_create(&th[i], NULL, soma, &tarefas[i]) != 0) {
            fprintf(stderr, "falha ao criar thread\n");
            return 1;
        }
    }
    long total = 0;
    for (int i = 0; i < THREADS; i++) {
        pthread_join(th[i], NULL);  /* espera e garante que o parcial já foi escrito */
        total += tarefas[i].parcial;
    }
    printf("total: %ld (esperado %ld)\n", total, N * (N + 1) / 2);
    return 0;
}
total: 50000005000000 (esperado 50000005000000)

Cada thread escreve só na própria Tarefa, e o main só lê os parciais depois do pthread_join, que garante que a escrita terminou e está visível. Não há dado compartilhado sendo escrito por duas threads ao mesmo tempo, então não há condição de corrida. Compile com -pthread.

Q70

Contador compartilhado com mutex

Crie 4 threads que incrementam um contador global 100.000 vezes cada. Mostre o resultado com o mutex protegendo o incremento e explique o que muda sem ele.

#include <stdio.h>
#include <pthread.h>

static long contador = 0;
static pthread_mutex_t trava = PTHREAD_MUTEX_INITIALIZER;

static void *incrementa(void *arg) {
    (void) arg;
    for (int i = 0; i < 100000; i++) {
        pthread_mutex_lock(&trava);
        contador++;  /* ler, somar e gravar: só uma thread por vez */
        pthread_mutex_unlock(&trava);
    }
    return NULL;
}

int main(void) {
    pthread_t th[4];
    for (int i = 0; i < 4; i++)
        pthread_create(&th[i], NULL, incrementa, NULL);
    for (int i = 0; i < 4; i++)
        pthread_join(th[i], NULL);
    printf("contador: %ld\n", contador);
    return 0;
}
contador: 400000

Sem o mutex, contador++ vira "ler, somar 1, gravar", e duas threads podem ler o mesmo valor e gravar o mesmo resultado: incrementos se perdem e o total fica abaixo de 400.000, variando a cada execução. Travar e destravar 400 mil vezes custa caro; num caso real, cada thread somaria num contador local e travaria uma única vez no fim, ou usaria atomic_long de <stdatomic.h>.

Q71

Encerrando com Ctrl+C

Escreva um programa que fica num laço "trabalhando" e, ao receber SIGINT, termina o laço de forma limpa e imprime quantas voltas deu. Para o teste ser automático, o próprio programa envia o sinal a si mesmo depois de 3 voltas com raise(SIGINT).

#define _POSIX_C_SOURCE 200809L
#include <stdio.h>
#include <signal.h>

static volatile sig_atomic_t parar = 0;

static void ao_interromper(int sinal) {
    (void) sinal;
    parar = 1;  /* só isso: o trabalho de verdade fica no laço principal */
}

int main(void) {
    struct sigaction sa = {0};
    sa.sa_handler = ao_interromper;
    sigemptyset(&sa.sa_mask);
    if (sigaction(SIGINT, &sa, NULL) < 0) {
        perror("sigaction");
        return 1;
    }

    long voltas = 0;
    while (!parar) {
        voltas++;  /* aqui entraria o trabalho real */
        if (voltas == 3)
            raise(SIGINT);  /* simula o Ctrl+C do usuário */
    }
    printf("encerrado com limpeza depois de %ld voltas\n", voltas);
    return 0;
}
encerrado com limpeza depois de 3 voltas

sigaction é preferível ao signal antigo, cujo comportamento varia entre sistemas. volatile sig_atomic_t garante que a escrita no tratador e a leitura no laço não sejam otimizadas nem divididas ao meio. Rodando de verdade no terminal, basta tirar o raise e apertar Ctrl+C.

Uma calculadora de terminal

Escreva uma calculadora de terminal com sete operações: soma, subtração, multiplicação, divisão, potência (expoente inteiro), porcentagem (15 % 200 é 15% de 200) e raiz quadrada (raiz 2). Ela deve: (a) aceitar vírgula ou ponto como separador decimal; (b) guardar o último resultado em ans, utilizável na conta seguinte; (c) recusar divisão por zero, raiz de negativo, expoente fracionário e texto que não é número com uma mensagem clara, sem encerrar o programa; (d) ter os comandos hist (histórico) e sair. Separe o núcleo (calc.c e calc.h, que não fazem entrada nem saída) da interface (main.c).

Caminho da solução

  • Núcleo: calc_avaliar recebe a linha e devolve um código de erro, com o resultado num parâmetro ponteiro (o padrão do módulo 8). As operações ficam numa tabela de símbolos, como no exercício de ponteiros para função.
  • Números: o strtod só entende ponto no locale padrão, então o núcleo troca a vírgula por ponto numa cópia do texto antes de converter. Os resultados são double, com os limites que isso traz (veja a nota depois da saída).
  • Interface: lê linhas com fgets, nunca com scanf, guarda o histórico num vetor dinâmico que cresce com realloc e libera tudo ao sair.

#ifndef CALC_H
#define CALC_H

typedef enum {
    CALC_OK,
    CALC_FORMATO,       /* linha que não é "a op b" nem "raiz a" */
    CALC_NUMERO,        /* operando que não é número */
    CALC_OPERACAO,      /* símbolo desconhecido */
    CALC_DIV_ZERO,
    CALC_RAIZ_NEGATIVA,
    CALC_EXPOENTE,
} CalcErro;

typedef struct {
    double ans;  /* último resultado */
} Calculadora;

/* Avalia "12,5 + 3", "2 ^ 10", "15 % 200" ou "raiz 2"; "ans" é o último resultado. */
CalcErro calc_avaliar(Calculadora *c, const char *linha, double *resultado);

calc.c:

#include "calc.h"

#include <ctype.h>
#include <errno.h>
#include <math.h>
#include <stdio.h>
#include <stdlib.h>
#include <string.h>

static CalcErro numero(const Calculadora *c, const char *texto, double *v) {
    if (strcmp(texto, "ans") == 0) {
        *v = c->ans;
        return CALC_OK;
    }
    char copia[64];
    if (strlen(texto) >= sizeof copia)
        return CALC_NUMERO;
    strcpy(copia, texto);
    char *virgula = strchr(copia, ',');
    if (virgula)
        *virgula = '.';  /* strtod segue o locale "C": só entende ponto */
    char *fim;
    errno = 0;
    *v = strtod(copia, &fim);
    if (fim == copia || *fim != '\0' || errno == ERANGE || !isfinite(*v))
        return CALC_NUMERO;
    return CALC_OK;
}

static CalcErro operar(char op, double a, double b, double *r) {
    switch (op) {
    case '+': *r = a + b; return CALC_OK;
    case '-': *r = a - b; return CALC_OK;
    case '*': *r = a * b; return CALC_OK;
    case '/':
        if (b == 0) return CALC_DIV_ZERO;
        *r = a / b;
        return CALC_OK;
    case '%': *r = a * b / 100; return CALC_OK;
    case '^':
        if (b != floor(b) || fabs(b) > 999) return CALC_EXPOENTE;
        if (a == 0 && b < 0) return CALC_DIV_ZERO;
        *r = pow(a, b);
        return CALC_OK;
    }
    return CALC_OPERACAO;
}

CalcErro calc_avaliar(Calculadora *c, const char *linha, double *resultado) {
    char t[3][64];
    int n = sscanf(linha, "%63s %63s %63s", t[0], t[1], t[2]);
    double a, b, r;
    CalcErro e;

    if (n == 2 && strcmp(t[0], "raiz") == 0) {
        if ((e = numero(c, t[1], &a)) != CALC_OK) return e;
        if (a < 0) return CALC_RAIZ_NEGATIVA;
        r = sqrt(a);
    } else if (n == 3 && strlen(t[1]) == 1) {
        if ((e = numero(c, t[0], &a)) != CALC_OK) return e;
        if ((e = numero(c, t[2], &b)) != CALC_OK) return e;
        if ((e = operar(t[1][0], a, b, &r)) != CALC_OK) return e;
    } else {
        return n == 3 ? CALC_OPERACAO : CALC_FORMATO;
    }
    if (!isfinite(r)) return CALC_NUMERO;  /* resultado grande demais para um double */
    c->ans = *resultado = r;
    return CALC_OK;
}

const char *calc_mensagem(CalcErro e) {
    static const char *m[] = {
        [CALC_OK] = "ok",
        [CALC_FORMATO] = "use: número operação número, ou raiz número",
        [CALC_NUMERO] = "não é um número válido",
        [CALC_OPERACAO] = "operação desconhecida",
        [CALC_DIV_ZERO] = "divisão por zero",
        [CALC_RAIZ_NEGATIVA] = "raiz de número negativo",
        [CALC_EXPOENTE] = "o expoente precisa ser inteiro, de -999 a 999",
    };
    return m[e];
}

/* 16 dígitos significativos, vírgula decimal e sem zeros à direita */
static void formata(double v, char *saida, size_t tam) {
    snprintf(saida, tam, "%.16g", v);
    char *ponto = strchr(saida, '.');
    if (ponto)
        *ponto = ',';
}

int main(void) {
    Calculadora calc = {0};
    char **historico = NULL;
    size_t n_hist = 0;
    char linha[256];

    puts("Calculadora: + - * / ^ % raiz  |  ans, hist, sair");
    for (printf("> "); fgets(linha, sizeof linha, stdin); printf("> ")) {
        linha[strcspn(linha, "\n")] = '\0';
        if (strcmp(linha, "sair") == 0)
            break;
        if (strcmp(linha, "hist") == 0) {
            for (size_t i = 0; i < n_hist; i++)
                puts(historico[i]);
            continue;
        }
        if (linha[0] == '\0')
            continue;

        double r;
        CalcErro e = calc_avaliar(&calc, linha, &r);
        if (e != CALC_OK) {
            printf("erro: %s\n", calc_mensagem(e));  /* a conta errada não derruba o programa */
            continue;
        }
        char num[64], conta[sizeof linha + 80];
        formata(r, num, sizeof num);
        snprintf(conta, sizeof conta, "%s = %s", linha, num);
        puts(conta);

        char **tmp = realloc(historico, (n_hist + 1) * sizeof *tmp);
        char *copia = malloc(strlen(conta) + 1);
        if (tmp == NULL || copia == NULL) {
            free(copia);
            historico = tmp ? tmp : historico;
            fputs("sem memória para o histórico\n", stderr);
            continue;
        }
        historico = tmp;
        historico[n_hist++] = strcpy(copia, conta);
    }
    for (size_t i = 0; i < n_hist; i++)
        free(historico[i]);
    free(historico);
    return 0;
}

Um mini-shell

Escreva um mini-shell que mostra um prompt, lê um comando com argumentos, executa-o num processo filho e espera o fim, e tem três comandos internos: cd, historico (os últimos 10 comandos, numa lista circular) e sair. Comandos inexistentes devem mostrar uma mensagem e devolver o prompt. Como extensão, implemente o redirecionamento > arquivo.

Caminho da solução

  • Leitura: fgets numa linha de até 1024 caracteres, separada em palavras com strtok num vetor char *argv[64] terminado em NULL, o formato que o execvp espera.
  • Comandos internos: precisam rodar no próprio shell. Um cd executado num filho mudaria o diretório do filho, que morre em seguida; por isso o shell testa argv[0] antes do fork e chama chdir diretamente.
  • Execução: fork; no filho, execvp(argv[0], argv) e, se ele voltar, perror e _exit(127); no pai, waitpid e o código de saída guardado para mostrar no prompt.
  • Histórico: um vetor de 10 char * com um índice que avança módulo 10 (a fila circular do módulo 7); ao sobrescrever uma posição, o free da string antiga vem antes.
  • Redirecionamento: no filho, antes do exec, open(arquivo, O_WRONLY | O_CREAT | O_TRUNC, 0644) e dup2(fd, STDOUT_FILENO); o > e o nome do arquivo saem do argv.
  • Sinais: o shell ignora SIGINT (Ctrl+C não deve matá-lo), e o filho restaura o comportamento padrão com signal(SIGINT, SIG_DFL) antes do exec, para que Ctrl+C interrompa só o comando em execução.

Teste com Valgrind ou -fsanitize=address: ao digitar sair depois de mais de 10 comandos, nenhuma string do histórico pode ter vazado.
